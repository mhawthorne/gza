# Release Notes: v0.4.0 → HEAD

## Summary

- **`gza watch` is a new, improved way to run gza.** It is a continuous, tag-scoped supervisor that picks up pending work, runs reviews, files improve tasks, and auto-merges approved units — with concurrency limits, failure backoff, no-progress backstops, and self-restart when gza's own code drifts.
- **Plan → review → sliced implement lifecycle.** `gza plan-review` gates a completed plan *before* any code is written, `gza plan-improve` revises it against review feedback, and an approved plan materializes as multiple right-sized implementation slices (a slice manifest) instead of one monolithic implement task. Plans can be held (`--hold-for-review`) so automation won't implement until you approve.
- **Highlights of other new commands:**
  - `gza tv` — live multi-task log dashboard.
  - `gza incomplete` — unresolved work grouped by merge-unit lineage owner.
  - `gza lineage` — merge-unit-grouped lineage tree view.
  - `gza search` — search task prompts with positive/negative filters.
  - `gza extract` — pull selected changes into a new task from a branch, commit, or path set.
  - `gza queue` — inspect and reorder the pending dispatch queue.  replaces `gza groups` and `gza group`.
  - `gza fix` — interactive rescue workflow for stuck tasks.
  - `gza plan-review` — quality-gate a plan before implementation (go/no-go).
  - `gza plan-improve` — revise a plan against review feedback.
  - _See [New commands](#new-commands) below for full descriptions._
- **Shared SQLite database** across worktrees/projects, with an explicit DB-location choice at `gza init` and read-only snapshots injected into task sandboxes.
- **Task IDs changed format** to project-prefixed IDs (`gza-1234`) in order to support a shared GZA database.
- **Merge units replace per-task merge status** as the model for what has landed, with a first-class `moot`/`empty` concept, lineage grouping, and reconciliation against real git truth.
- **Multi-valued tags replace groups**; `gza group`/`gza groups` are retired.
- Major performance work: `gza queue`, `gza incomplete`, `gza lineage`, and the watch cycle went from tens of seconds to sub-second on large databases; the unit test suite was made hermetic and fast.

## Breaking Changes

- **Task ID format**: IDs are now project-prefixed (`gza-1234`), with a variable-length decimal suffix. Shorthand IDs, legacy IDs, and the `#` display prefix are gone.
- **`gza group` / `gza groups` removed** — replaced by first-class multi-valued `--tag`. All task-add and execution commands take `--tag`.
- **`gza cycle` removed** (legacy subcommand).
- **`gza import` removed**, along with its entire import subsystem.
- **`gza refresh` removed.**
- **`gza stop` replaced by `gza kill`.**
- **`gza cleanup` replaced by `gza clean`** with `--archive`, `--purge`, and `--backups` modes.
- **`gza status` alias for `gza ps` removed.**
- **`gza history --incomplete` and `--lineage-depth` removed**; `gza incomplete --tree` removed. Use `gza lineage`.
- **`gza search --related-to` deprecated/removed.**
- **`gza merge` only permitted on default branches.**
- **`set-status` no longer accepts `in_progress`** and enforces state-transition rules; `dropped` requires `--reason`.
- **`allow-noop-improve` tag removed.**
- **Branch naming**: `{task_id}` template variable renamed to `{task_slug}`; new `{task_id}` is the short ID; `monorepo` branch preset removed in favor of the new default `project_date_slug`.
- **`.venv` is no longer mounted into task containers**, and the `uv` fallback in the container shim was removed.
- **Default provider changed to Codex**; default Codex model bumped.

## Features

### Watch & autonomous operation
- `gza watch`: continuous scheduler with per-cycle dry-run preview and confirm gate (`-y` to skip), tag scoping (OR-matching by default), `--restart-failed` recovery mode, and immediate re-exec on installed-code drift.
- Auto-merge after a successful review, including "approved with follow-ups".
- `advance_mode: iterate` config — folds review/improve into a single held slot so a unit is driven to completion rather than interleaved step-at-a-time.
- Failure backoff (`failure_backoff_initial`, `failure_backoff_max`, `failure_halt_after`), scoped per-task rather than globally.
- No-progress backstop that measures progress by outcome and escalates to ATTENTION.
- `watch.no_activity_timeout` for the worker-kill threshold; system-wide `max_concurrent` task limit.
- Main-verify remediation loop (MV4): detects red local main, files bounded remediation fixes, and auto-expires stale red checkpoints.
- Post-merge integration verify gate on local main, flake-tolerant with deterministic-red handling.

### New commands
- `gza tv` — live multi-task log dashboard with dynamic slot sizing (`--min`/`--max`), per-panel step count, duration, tokens, and cost.
- `gza sync` — explicit git and GitHub reconciliation.
- `gza preflight` — live environment/provider check.
- `gza incomplete` — unresolved work by merge-unit lineage owner.
- `gza lineage` — merge-unit-grouped lineage view with local window by default (`--full`, `--flat`, `--json`).
- `gza search <term>` — unified task search with negative filters and a result-summary footer.
- `gza extract` — extract selected changes into a new task, from a branch, commit, or path set; `--dry-run` supported.
- `gza queue` — explicit queue ordering with `move`/`next`/`clear`, `-n/--limit`, `--all`.
- `gza fix` — interactive rescue workflow for stuck tasks, with `--review`.
- `gza plan-review` — quality-gate a completed plan before implementation; emits an approved slice manifest or `CHANGES_REQUESTED`, with `--run`, `--edit-slices`, and `--materialize`.
- `gza plan-improve` — create/run a `plan_improve` task to revise a plan after a `CHANGES_REQUESTED` plan review.
- `gza run-inline` — first-class inline (in-conversation) task execution.
- `gza stats reviews` and `gza stats iterations` — review quality scores and iteration analytics.
- `gza config keys` — discoverable config registry.

### Task model & lifecycle
- Merge units as the unit of merge truth, with `merge_source` provenance, owner-task tracking, and a per-unit branch (no folding).
- First-class `moot`/`empty` task concept; `empty` and `merged` are now distinct states.
- Blocked-task model — tasks with unsatisfied dependencies or a dirty main checkout surface as blocked rather than silently failing.
- Task comments system, with comments-only `gza improve` when no review exists.
- **Plan-review lifecycle.** Completed plans can be held with `--hold-for-review` (released via `--no-hold-for-review`) so automation won't implement them until approved. `gza plan-review` runs a structured quality gate that emits a machine-readable slice manifest; `gza plan-improve` revises a plan after `CHANGES_REQUESTED`. On approval the plan materializes as multiple right-sized implement slices (bounded by `max_plan_slices` and diff-size sizing) rather than one monolithic implement task. `require_plan_review_before_implement` enforces the gate, and `max_plan_review_cycles` bounds review/improve churn.
- Recovery engine: unified automatic recovery policy, resume vs retry classification, re-spawn circuit breaker, stale-unmerged sweep, and a durable per-task artifact store.
- Severity-tiered review verdicts (blockers vs non-blocking follow-ups); derived 0–100 review quality score.
- Provider/model parity gate so a task can never run on a mismatched provider; `CONFIG_ERROR` classification for provider config problems.
- Interactive attach to running tasks via tmux (`gza attach`), including Docker-backed tasks.
- GitHub PR integration: `--pr` on `gza work`, PR publication after reconcile, issue linking, and unified PR title/body generation.
- Read-only task-DB snapshot injected into task sandboxes.

### Config & setup
- Shared DB model with explicit DB-location choice in `gza init`; readable derived `project_id`.
- User-level config file for per-user defaults; local config overrides now deep-merge instead of clobbering.
- Configurable Codex `reasoning_effort`; per-provider Docker image tags; `docker_setup_command` pre-warm hook.
- Config switch to disable all automatic recovery.
- Color theme system for terminal output, applied across `ps`, `watch`, `advance`, and task output.

## Bug Fixes

- Fixed the watch iterate livelock where `create_review` no-ops parked tasks and starved runnable work.
- Stopped watch re-proving already-merged terminal leaves (removed the origin-branch merge-source fallback and the `verify origin/<branch>` stderr spam).
- Fixed Docker-backed runs poisoning shared host git state — container `.git`/`commondir` are now bind-mounted instead of rewritten in place, so concurrent host git ops no longer fail fleet-wide with `Invalid path '/gza-git'`.
- Fixed detached/broken worktrees being misclassified as no-op, and `git worktree prune` reaping live worktrees.
- Fixed rebase failures: legacy tasks with NULL `base_branch`, `review_scope` clobbering rebase-diff provenance, no-op rebase loops, transiently-failed rebases never auto-recovering, and infra-caused (read-only DB) rebase failures.
- Fixed `gza show` crashing on square brackets in prompts and on `sqlite3` errors; added PR fields and worktree path to output.
- Fixed `gza ps`: runaway runtime on completed tasks, false "stale" labels, hardcoded task-ID color, column alignment; added lineage and date sort modes.
- Fixed `gza unmerged`: branchless ancestors, stale review verdicts, duplicate review rows, and unnecessary origin fetches.
- Fixed `gza tv` dropping just-completed tasks and losing error messages.
- Fixed `gza iterate` orphaning pending tasks, stopping after a single cycle with `-b`, and mis-counting iterations (`-i N` now means N).
- Fixed `gza log` showing the wrong task's log and dropping top-level error events.
- Fixed a race allowing duplicate task execution in `gza watch` between worker start and the in-progress DB write.
- Fixed worker liveness: zombie-aware reaping, PID-reuse guards, double-registration leaks, and premature pruning of freshly spawned workers.
- Fixed failed closing reviews satisfying the review gate, and scope violations auto-proceeding instead of parking.
- Fixed `plan_improve` looping forever at max plan-review cycles, and held-for-review plans deadlocking their dependents.
- Fixed gza leaking its own `.gza/` artifacts into task commits.
- Fixed host timeout (exit 124) misclassification and Docker daemon crashes being reported as provider errors.
- Fixed the `.env` mount not being writable in Docker and the hardcoded `.venv` tmpfs path.
- Eliminated "Node.js 20 is deprecated" warnings and repaired the GitHub Actions `Test` workflow.

## Improvements

### Performance
- `gza queue` now defaults to a git-free pending scan; remaining latency cut further.
- `gza incomplete` short-circuits merged/resolved rows and wraps git work in bounded operations.
- Lineage traversal memoized by root ID; `gza lineage` made fast on a 1.6 GB database.
- Watch cycle no longer double-computes its first pass or recomputes owner rows twice.
- SQLite pragma setup applied once per store; theme color conversion no longer deep-copies.

### Testing & CI
- Unit suite made hermetic: subprocess- and git-heavy tests relocated to a `functional` lane, whole-codebase scanners moved out, real-git tests converted to mocks.
- Local verify now reproduces CI's xdist behavior; per-test timeout watchdog split into hang-guard plus CPU-time gate.
- `bin/tests --integration` makes integration tests opt-in.

### Output & UX
- Watch merge logging collapsed to one `MERGE` line; lifecycle advance actions made visible; recovery-vs-pending distinction surfaced.
- Lineage rendering unified across `lineage`, `show`, `history`, and `unmerged` into one grouped view with one-line summaries.
- Failure explanations from the agent surfaced on failed tasks.
- Codex/Claude log parsing: provider-owned renderers, reasoning/thinking blocks, tool-activity item types, control and error events, and unknown events rendered as raw JSON instead of dropped.
- Model and provider now logged per run; cost and token metrics captured for interrupted runs.

### Scripts & tooling
- `scripts/watch_log_graph.py` — graphs watch queue depth, merges, and cycle activity over time, with `--hours`/`--start`/`--all`, resolution and aggregation options, live `--watch` mode, and readable merge-box layout.
- `scripts/revive_stuck.py` — `next_action`-driven overnight reviver for stuck tasks.
- Helper scripts for worktree repair, `.gza` symlinking, task hunk diffs, review-score backfill, and iteration analysis.

## Skills

- New skills:
  - `gza-task-fix` — rescue a stuck task inline: verify each review/improve blocker against current code, fix the open ones, run verify, commit.
  - `gza-task-triage` — classify each unresolved `gza incomplete` lineage and recommend the right corrective action.
  - `gza-task-review` — interactive code review of a task's implementation branch, always running `verify_command`, with `gza-task-improve`-compatible output.
  - `gza-task-improve` — address a task's review findings and/or unresolved comments inline, then verify and commit.
  - `gza-task-run` — compatibility wrapper that routes inline task execution to `gza run-inline`.
  - `gza-plan-review` — interactive quality gate for a plan task; produces a go/no-go before implementation.
  - `gza-plan-improve` — refine a draft plan via targeted questions and gap-resolution into an implementation-ready plan.
  - `gza-spec-review` — interactive quality gate for a spec file; produces a go/no-go before implementation.
  - `gza-explore-summarize` — summarize an explore task's findings and suggest concrete next steps.
  - `gza-log-insights` — mine run logs for recurring anti-patterns and wasted effort, and suggest AGENTS.md/workflow improvements.
- Skills detect the base branch dynamically instead of hardcoding `main`.
- Task-creation skills prefer temp files over heredocs for long prompts.
