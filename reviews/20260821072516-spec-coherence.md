## Summary

Targeted closure checks:

- `watch-supervisor.md` owns the multi-project dispatch-capacity equation:
  `aggregate_running` remains task-executing only, while `aggregate_occupied` deduplicates
  task-executing workers, starting workers, and unsettled reservations before computing
  `dispatch_slots`. No other behavior spec defines a competing watch capacity formula.
- `watch-supervisor.md` owns fleet worker-consuming lane arbitration: recovery heads are
  selected up to one supervisor-global recovery allocation before pending heads receive
  remaining capacity, unused recovery allocation is donated to pending in the same cycle,
  and round-robin cursor/quota state is separated by lane.
- `watch.failure_halt_after`, failure-streak, halt, and hold clauses now use one ownership model: failure aggregation and halt threshold are project-runtime local; multi-project mode holds only the owning runtime; legacy single-project mode retains its one-runtime stop behavior.
- Aggregate supervisor state and logging now resolve through one deterministic rule: explicit override, then manifest-directory default, then anchor-project fallback. The observability section and settled compatibility choices name the same three ordered cases.
- Health and capacity are separate concepts: every selected runtime contributes known live task-executing workers, starting workers, and unsettled reservations to aggregate occupancy, while disabled, held, capped, and launch-blocked runtimes expose no new candidate and take no new reservation.
- Unkeyed tag flags now use one predicate: accepted when the invocation resolves exactly one execution project, including one explicit `--watch-project`, and rejected when the invocation resolves more than one execution project.
- `main-verify-self-heal.md` states only the red-main ownership boundary for deterministic integration-verify failures: the hold applies to ordinary merge actions for the affected local target/merge lane, must not suppress the bounded remediation path for the same failure identity, and must not block healthy project runtimes in a multi-project watch fleet. That cross-reference is consistent with `watch-supervisor.md` owning per-runtime health isolation and fleet dispatch eligibility.
